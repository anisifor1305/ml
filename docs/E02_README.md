# E02: сервис тональности и анализ поездок

Локальный FastAPI-сервис определяет тональность русского текста; отдельный слой
SQL и EDA закрепляет подготовку данных. Поездки такси не передаются модели текста.

## Окружение и установка

Работа проверялась на macOS ARM64, Python 3.9.6. Модель работает на CPU.
Из корня репозитория, при создании нового окружения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -r requirements-lesson13.txt -r requirements-e02.txt -r requirements-e02-model.txt -e '.[visualization]'
```

Существующее окружение уже настроено, повторная установка для сдачи не нужна.
Версии API-библиотек и модели закреплены в requirements-e02*.txt.

## Модель

Имя: cointegrated/rubert-tiny-sentiment-balanced.
Ревизия: e0679dd4460e48648f5d4d819ae0f505384f5a9d.
Источник: https://huggingface.co/cointegrated/rubert-tiny-sentiment-balanced.
Загрузчик: src/mldata/e02_model.py; исполняемый код из репозитория модели не требуется.
Вход: JSON с обязательным строковым text, 1–500 символов.
Выход: label (negative, neutral, positive) и score от 0 до 1.
Score — оценка категории моделью, не гарантия правильности.
Непустая строка из пробелов пока проходит проверку длины: дополнительной
нормализации пробелов на этих этапах не вводили.
Первый запуск скачивает модель, последующие используют кэш Hugging Face.
Текст обрабатывается локально. Загрузка выполняется в lifespan один раз на процесс.

## Запуск и запросы

В первом терминале:

```bash
.venv/bin/python exercises/e02_service.py
```

Сервис слушает только локальный адрес 127.0.0.1:8000.
Документация: http://127.0.0.1:8000/docs. Остановка: Ctrl+C.

Во втором терминале:

```bash
curl http://127.0.0.1:8000/health
curl -X POST http://127.0.0.1:8000/predict -H 'Content-Type: application/json' -d '{"text":"Отличный товар, всё понравилось!"}'
```

Первый ответ: {"status":"ok"}. Второй — JSON с label и score; точные числа
не фиксируем в инструкции. /inspect возвращает длину текста, без вызова модели.
Ошибочные входные данные дают 422. RuntimeError вычисления — 500 с detail;
подробности записываются в журнал. Ошибка загрузки модели прерывает запуск.

Пример отдельного Python-клиента: exercises/e02_client.py.
Функцию request_prediction заполняет ученик на этапе 8, затем запускает:

```bash
.venv/bin/python exercises/e02_client.py
```

Она отправляет HTTP-запрос работающему сервису. Не импортирует приложение и
не загружает вторую модель. Вывод — словарь предсказания в формате JSON.

## Проверки, SQL и графики

```bash
.venv/bin/python -m pytest tests/e02 -v
.venv/bin/python exercises/e02_sql.py
.venv/bin/python exercises/e02_eda.py
```

API-тесты используют тестовую замену модели: проверяют работу API, не качество
реальной нейросети. Реальное предсказание проверяется отдельно запросом к серверу.
SQL: 8 запросов в exercises/sql/e02/, включая итоговую витрину 08.sql.
База SQLite создаётся в памяти из CSV, сервер базы и Docker не нужны.
Выход: exercises/outputs/e02/sql_01.csv ... sql_08.csv.
Витрина 08.sql содержит 159 поездок и историю, завершившуюся до 15 марта 2019.

Данные: exercises/data/e02/. Источник — taxis.csv из mwaskom/seaborn-data;
точный URL и SHA-256 исходника находятся в source.json. Для SQL/EDA выбраны
первые 300 строк; справочник зон подготовлен из полного исходника.
Рисунки и профиль: exercises/outputs/e02/eda/.
Итоговая стоимость, фактическое расстояние и чаевые текущей поездки нельзя брать
как известные признаки при прогнозе в начале поездки. Статистики не должны
использовать будущие наблюдения; копии объектов не должны пересекать обучение
и проверку. Одна выборка не доказывает представительность всех поездок города.

## Учёт ресурсов

GPU-проба Colab выполнена; исходный результат: docs/e02_resources/gpu_result.json.
Время в JSON — замер одной операции, НЕ продолжительность аренды GPU.
Сводный журнал: docs/GPU_USAGE.csv. Неизвестные фактические значения оставлены
пустыми: длительность сессии и стоимость не восстанавливаем из времени операции.

## Критерий завершения этапа 8

1. Реализован и запущен Python-клиент.
2. Выполнены оба curl-запроса к реально работающему сервису.
3. Проверены команды тестов, SQL и EDA (ассистент повторяет перед сдачей).
4. Известные данные GPU-пробы записаны; неизвестные помечены как неизвестные.
5. Пользователь понимает команды запуска и может остановить сервер.

Публикация сервиса в интернете и Docker не входят в эту сессию.
