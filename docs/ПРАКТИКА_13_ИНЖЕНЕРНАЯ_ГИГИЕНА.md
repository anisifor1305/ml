Микро-пример синтаксиса логирования на другой задаче:

```python
LOGGER.info("Загружено %d книг", 12)

```

Округление сообщения не должно округлять сам сохранённый результат.

## Задание 4. Аргументы командной строки

Функция `parse_args(argv=None)` должна описать:

| Аргумент | Тип | Значение, если не передан |
|---|---|---|
| --config | Path | DEFAULT_CONFIG (готовая константа) |
| --output | Path | DEFAULT_OUTPUT (готовая константа) |
| --seed | int | None |

Верни результат `parser.parse_args(argv)`.
Важное отличие от микро-примера лекции: мы передаём argv в parse_args.
Если argv равен None, argparse читает настоящую командную строку.
Если argv — список строк, argparse разбирает этот список. Это нужно тестам.
Например, тест может передать `['--seed', '17']`, не запуская отдельный терминал.

Не переопределяй сид в этой функции: она только читает аргументы.
Готовая main передаст args.seed в твою load_config.
Справку --help умеет показывать сам argparse.

```bash
.venv/bin/python -m pytest tests/lesson_13/test_acceptance.py -k cli
.venv/bin/python exercises/lesson_13.py --help
```

После четырёх функций можно запустить весь эксперимент:

```bash
.venv/bin/python exercises/lesson_13.py --config configs/lesson_13.yaml --output exercises/outputs/lesson_13/first
.venv/bin/python exercises/lesson_13.py --config configs/lesson_13.yaml --output exercises/outputs/lesson_13/second
.venv/bin/python exercises/lesson_13.py --config configs/lesson_13.yaml --seed 17 --output exercises/outputs/lesson_13/other_seed
```

Три отдельные команды: первая и вторая с сидом 42, третья с сидом 17.
Указывай разные папки: повторный запуск в ту же папку перезаписывает результаты.

В каждой папке появятся:

| Файл | Содержание |
|---|---|
| distances.npy | Матрица расстояний в формате NumPy |
| metrics.json | Сид, размеры и среднее расстояние |
| config.yaml | Настройки, фактически использованные в этом запуске |
| experiment.log | Сообщения о начале, итоге и сохранении |

Числовой массив и метрики двух запусков с одним сидом должны совпасть побитово
в текущем окружении. С сидом 17 массив и среднее изменятся. Это свойство нашего
эксперимента: вообще разные сиды не обязаны менять любой возможный показатель.
Логи и имена папок сравнивать побитово не нужно. Скорость не измеряем.

## Задание 5. Написать три своих теста

Открой `tests/lesson_13/test_student.py` и реализуй три обозначенных теста:

1. Расстояние между (0, 0) и (3, 4) равно 5. Ожидаемый результат — матрица (1, 1).
2. Для выбранной тобой одинаковой точки расстояние до самой себя равно 0.
3. После расчёта оба входных массива не изменились.

Никаких больших случайных датасетов: это маленькие примеры с понятным ответом.
Импорт NumPy и необходимые проверки добавь сам.

Новые инструменты, до использования:

- `np.testing.assert_allclose(actual, expected, atol=...)` сравнивает форму и числа
  массивов с допуском: небольшая погрешность float разрешена. При несовпадении
  возникает AssertionError; отдельный assert перед вызовом не нужен.
- `np.testing.assert_array_equal(actual, expected)` проверяет форму и точные
  значения элементов. Уместно для проверки сохранности входных данных.
- `.copy()` делает независимую копию NumPy-массива, с которой можно сравнить
  массив после вызова функции.

На постороннем примере:

```python
np.testing.assert_allclose([0.1 + 0.2], [0.3], atol=1e-12)
np.testing.assert_array_equal([2, 7], [2, 7])
```

Функция теста может ничего не возвращать: если все проверки прошли без исключения,
pytest считает её успешной.

```bash
.venv/bin/python -m pytest tests/lesson_13/test_student.py
```
