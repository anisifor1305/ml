## Ссылки, изменения и копии

```python
a = [1, 2]
b = a
b.append(3)
# a тоже стал [1, 2, 3]
```

`a` и `b` — два имени одного списка. Для поверхностной копии:

```python
b = a.copy()
```

Но у вложенных списков внутренние объекты всё ещё могут быть общими.

## Как выбрать контейнер

| Нужно | Контейнер |
|---|---|
| Порядок, дубликаты, можно менять | `list` |
| Фиксированная неизменяемая запись | `tuple` |
| Быстро проверить наличие, убрать дубликаты | `set` |
| Найти значение по имени / ключу | `dict` |
| Посчитать частоты | `Counter` |
| Собрать много значений по одному ключу | `defaultdict(list)` |

`x in list` — O(n), `x in set` и `key in dict` — в среднем O(1).

## Список: похожие операции делают разное

```python
items.pop()  # удалить и вернуть последний элемент
items.pop(0)  # удалить и вернуть первый; медленно на длинном списке
del items[0]  # удалить первый, ничего не вернуть
items.remove(x)  # удалить первое найденное значение x
```

`pop(0)` и `del items[0]` — O(n): остальным элементам надо сдвинуться.

## `dict.fromkeys`

Убирает дубликаты, сохраняя порядок первого появления:

```python
unique = list(dict.fromkeys(["cat", "dog", "cat", "bird"]))
# ["cat", "dog", "bird"]
```

Не передавай туда изменяемое общее значение:

```python
bad = dict.fromkeys(["a", "b"], [])
# bad["a"] и bad["b"] — один и тот же список
```

## Распаковка: `*` и `**`

`*` работает с последовательностями и позиционными аргументами:

`**` работает со словарями и именованными аргументами:

```python
train(**{"learning_rate": 0.001, "epochs": 10})

```

## Сортировка и поиск лучшего

```python
models.sort(key=lambda model: model["accuracy"], reverse=True)
```

`list.sort()` меняет список на месте и возвращает `None`. `sorted(...)` создаёт новый список.

## `None` и значения по умолчанию

Неправильно:

```python
def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags
```

Список создаётся один раз и делится между вызовами.

Правильно:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

Для `None` используй `is None`, не `== None`.

В dataclass для нового списка у каждого объекта:

```python
from dataclasses import dataclass, field


@dataclass
class Config:
    tags: list[str] = field(default_factory=list)
```

## Классы: `self` и специальные методы

Ты не передаёшь `self` вручную:

```python
dataset = TableDataset(features, targets)
# Python примерно вызывает:
# TableDataset.__init__(dataset, features, targets)
```

`self.features` сохраняет данные внутри конкретного объекта.

| Метод | Что даёт |
|---|---|
| `__init__` | создание и настройка объекта |
| `__len__` | `len(object)` |
| `__getitem__` | `object[index]` |
| `__repr__` | понятный вывод объекта |
| `__call__` | `object(...)` |

`__post_init__` запускается автоматически **только у `@dataclass`**. В обычном классе проверки надо делать в `__init__`.

## Аннотации типов и Python 3.9

```python
def __getitem__(self, index: int) -> tuple[list[float], int]: ...
```

Аннотация описывает то, что реально возвращается. Если метод отдаёт `([1.0, 2.0], 0)`, это `tuple[list[float], int]`, а не «два списка».

В текущем Python 3.9 для опционального списка используй:

```python
from typing import Optional

tags: Optional[list[str]] = None
```

Синтаксис `list[str] | None` рассчитан на Python 3.10+.

# Занятие 04: Потоки, память и генераторы

## Итератор против Генератора

* **Итератор** — это протокол: объект с методами `__iter__()` (возвращает `self`) и `__next__()` (возвращает следующее значение или бросает `StopIteration`).
* **Генератор** — функция со словом `yield`. Python сам превращает её в итератор.

```python
# Итератор вручную через класс:
class StreamRange:
    def __init__(self, start, stop, step=1):
        self.current = start
        self.stop = stop
        self.step = step

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.stop:
            raise StopIteration
        val = self.current
        self.current += self.step
        return val
```

## `yield` — это пауза, а не смерть функции

* `return` возвращает значение и уничтожает локальные переменные функции.
* `yield` отдает значение наружу и **замораживает состояние функции** ровно на этой строчке. При следующем вызове `next()` функция возобновляется со следующей строчки.

```python
def batch_stream(data, batch_size):
    batch = []
    for item in data:
        batch.append(item)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch
```

## Память: `[...]` против `(...)`

```python
# List comprehension: сразу аллоцирует массив в RAM (~38-40 МБ на 1 млн чисел)
list_data = [x**2 for x in range(1_000_000)]

# Generator expression: создает легковесный объект (~112 байт вне зависимости от N)
gen_data = (x**2 for x in range(1_000_000))
```
В цикле `sum(gen_data)` в памяти в любой момент времени находится только одно число.

## Строки в датасетах: скрытая ловушка `\n`

При построчном чтении файлов `for line in f:` в конце строки остается невидимый перенос `\n`:
```python
label1 = "cat\n"
label2 = "cat"
print(label1 == label2)  # False! Классы разойдутся!
```
Всегда чисти края строк через `.strip()`:
* `.strip()` — срезает `\n`, пробелы и табуляции с обоих концов.
* `.rstrip()` — только справа.

## Контекстные менеджеры и `@contextmanager`

`with` гарантирует уборку ресурсов (файлов, памяти, таймеров) даже при падении программы.

Под капотом `with` вызывает:
1. `__enter__` — перед входом.
2. `__exit__` — при любом выходе (даже при падении с ошибкой).

Через `@contextmanager` из `contextlib`:
```python
from contextlib import contextmanager
import tracemalloc


@contextmanager
def track_memory(name: str):
    tracemalloc.start()  # аналог __enter__
    try:
        yield  # пауза: выполняется блок with
    finally:
        # аналог __exit__: сработает ВСЕГДА
        current, peak = tracemalloc.get_traced_memory()
        tracemalloc.stop()
        print(f"[{name}] Пик: {peak / 1024 / 1024:.2f} МБ")
```

## Почему `except: pass` убивает обучение в ML

Никогда не глуши ошибки голым `pass`:
```python
# АНТИПАТТЕРН: модель учится на нулях/мусоре 10 часов без единой ошибки в консоли
try:
    data = load_image(path)
except:
    pass
```
Всегда либо логируй, либо пробрасывай с контекстом через `from`:
```python
try:
    val = float(raw_str)
except ValueError as err:
    raise ValueError(f"Ошибка в строке датасета {row_id}: не число {raw_str!r}") from err
```
`from err` сохраняет первопричину в поле `__cause__` и формирует понятный стек вызовов.

# Занятие 05–06: NumPy, память и векторизация

## Устройство `ndarray` в памяти: Буфер + Паспорт

Массив NumPy состоит из двух независимых частей:
1. **Буфер данных:** непрерывная одномерная лента сырых байт в C-памяти (`[1, 2, 3, 4, 5, 6]`).
2. **Паспорт (Header):** метаданные — `dtype`, `shape` и `strides`.

**`strides` (шаги в байтах)** — смещение в памяти при переходе к следующему элементу по каждой оси.

## `float32` vs `float64` в ML

* По умолчанию в NumPy: `float64` (8 байт на число).
* Стандарт в машинном обучении: `float32` (4 байта на число).
* **Выигрыш:** экономия оперативной памяти и VRAM ровно в 2 раза; ускорение вычислений на GPU в 2–4 раза. Точности 6 знаков после запятой для градиентов более чем достаточно.

## Views (представления) vs Copies (копии)

* Базовый срез `sub = arr[1:3]` возвращает **View** (смотрит в тот же буфер памяти). Изменение `sub[0] = 999` испортит исходный массив `arr`!
* Для безопасной изоляции вызывай `.copy()`: `sub = arr[1:3].copy()`.
* **Fancy indexing** (`arr[[0, 2, 4]]`) и булевы маски (`arr[arr > 0]`) **всегда создают копию**, так как шаги `strides` нерегулярны.

## `reshape` vs Транспонирование (`.T`)

У обоих вариантов форма может быть одинаковой (например, `(3, 2)`), но содержимое принципиально разное:
* **`reshape(3, 2)`** считывает элементы подряд слева направо и перекладывает в новую сетку (разрывает строки/признаки!).
* **`arr.T`** математически меняет строки со столбцами (меняет местами оси в `shape` и `strides`). Сами числа в памяти никуда не перемещаются!

**Трюк с `-1`:** `arr.reshape(-1, 2)` — NumPy сам вычисляет размерность через деление `total_elements / 2`.

## Параметр `axis` в 2D-матрицах

* **`axis=0`** — вертикально (сверху вниз). Схлопывает строки, результат считается для каждого **столбца**.
* **`axis=1`** — горизонтально (слева направо). Схлопывает столбцы, результат считается для каждой **строки**.
* Без параметра (`arr.sum()`, `arr.mean()`) — схлопывает вообще всю матрицу в одно число.

## Железные правила Broadcasting

NumPy позволяет делать операции над массивами разных форм без копирования памяти:

1. **Выравнивание:** формы прижимаются **к правому краю**, пустые места слева заполняются единицами `1`.
   * `(2, 3)` и `(3,)` $\rightarrow$ `(2, 3)` и `(1, 3)`.
2. **Проверка по каждой позиции:** размеры совместимы, если:
   * они равны ($dim_A == dim_B$),
   * **ИЛИ один из них равен `1`** (размерность 1 виртуально растягивается до соседа).
3. **Смысл:**
   * Одинаковые формы: операция «один-к-одному» (поэлементно).
   * Формы со столбцом `(N, 1)` и строкой `(1, M)`: операция «каждый с каждым» (все возможные комбинации, как таблица умножения Пифагора).
4. Если числа разные и единицы нет $\rightarrow$ `ValueError: operands could not be broadcast together`.

### Паттерн: попарные евклидовы расстояния без циклов (N×M)
Разница между всеми точками $A$ $(N, D)$ и $B$ $(M, D)$ в один шаг:
```python
# A[:, np.newaxis, :] имеет форму (N, 1, D)
# B[np.newaxis, :, :] имеет форму (1, M, D)
diff = A[:, np.newaxis, :] - B[np.newaxis, :, :]  # (N, M, D)
dists = np.sqrt(np.sum(diff**2, axis=-1))  # (N, M)
```
Даёт ускорение в 50–100 раз по сравнению с двойным циклом `for`.


## Булева индексация и условия

В NumPy словесные `and`, `or`, `not` **не работают над массивами**. Используй битовые операторы и **обязательные круглые скобки**:
* `&` — логическое И
* `|` — логическое ИЛИ
* `~` — логическое НЕ

```python
# Фильтрация по диапазону:
filtered = scores[(scores >= 70) & (scores <= 90)]

# Зануление отрицательных (ReLU):
arr[arr < 0] = 0
```

## `np.where` и `np.clip`

```python
# Тернарный оператор над массивом:
classes = np.where(probs >= 0.5, 1, 0)

# Зажатие чисел в диапазон (защита от переполнения и взрыва градиентов):
clipped = np.clip(values, 0.0, 1.0)
```

## Воспроизводимый рандом (`default_rng`)

Вместо устаревшего `np.random.seed(42)` используй современный стандарт NumPy:
```python
rng = np.random.default_rng(seed=42)
ints = rng.integers(0, 10, size=(2, 3))
floats = rng.random(size=(3, 3))
normal = rng.normal(loc=0.0, scale=1.0, size=(1000,))
```

## Численная устойчивость: `inf` и `nan`

* `np.isnan(arr)` — поиск Not a Number (результат деления 0/0).
* `np.isinf(arr)` — поиск переполнения бесконечностью (overflow).
* `np.all(np.isfinite(arr))` — быстрая проверка, что все числа в тензоре корректны.
* `np.nan_to_num(arr, nan=0.0)` — безопасная замена битых значений.

# Занятие 07: pandas, индексация и память

## Зачем pandas, если есть NumPy?

* В NumPy все ячейки обязаны быть одного типа (например, все `float32`).
* `DataFrame` в pandas позволяет держать разнородные типы колонок в одной таблице (`int`, `float`, `str`, `bool`, `datetime`). Внутри каждая колонка чисел — это тот же самый C-массив NumPy.

## Parquet против CSV: почему в ML выбирают Parquet

* CSV — простой текст без схемы. При каждом чтении pandas заново угадывает типы (медленно и часто с ошибками).
* **Parquet** — бинарный колоночный сжатый формат.
  * Весит в 4–6 раз меньше на диске.
  * Читается в 5–10 раз быстрее.
  * Жестко сохраняет `dtypes` колонок.

## `loc` против `iloc`: разбор до автоматизма

Синтаксис обоих: `[строки, колонки]`.

| Свойство | `.iloc` (Integer Location) | `.loc` (Label Location) |
|---|---|---|
| По чему ищет | **Строго по номерам позиций** (0, 1, 2...) | **По именам колонок и меткам строк** |
| Правая граница среза | **НЕ включается** (`0:5` вернет 0, 1, 2, 3, 4) | **ВКЛЮЧАЕТСЯ** (`10:15` вернет 10, 11, 12, 13, 14, 15) |
| Примеры | `df.iloc[:5, :3]`, `df.iloc[-1, -1]` | `df.loc[10:15, ['city', 'spend']]`, `df.loc[42, 'age']` |

## Булева фильтрация: почему скобки обязательны

В pandas `and` / `or` не работают. Используются `&` и `|`.  
Поскольку у битовых операторов приоритет выше, чем у `<` или `==`, **каждое условие ОБЯЗАТЕЛЬНО оборачивать в круглые скобки**:

```python
# ПРАВИЛЬНО:
df[(df["city"] == "Москва") & (df["age"] < 30)]

# ОШИБКА TypeError (Python пытается вычислить 'Москва' & df['age']):
df[df["city"] == "Москва" & df["age"] < 30]
```

## `SettingWithCopyWarning`: главная ловушка модификации

```python
# АНТИПАТТЕРН (Chained Indexing):
df[df["age"] > 25]["salary"] += 5000  # Вылетит предупреждение, в df данные могут НЕ измениться!
```

### Как делать правильно:
1. **Если нужен отдельный датафрейм:** явно вызывай `.copy()`:
   ```python
   seniors = df[df["age"] > 25].copy()
   seniors["bonus"] = 5000
   ```
2. **Если нужно изменить данные прямо в исходном `df`:** всегда используй `.loc`:
   ```python
   df.loc[df["age"] > 25, "salary"] += 5000
   ```

## Оптимизация памяти (Downcasting и `category`)

Колонки со строками (`object`) хранят ссылки на питоновские объекты и раздувают память в разы.

* **Тип `category`:** повторяющиеся строки (города, устройства, статусы) кодируются 8-битными числами со словарем. Сжимает память текстовых колонок в 10–80 раз:
  ```python
  df["city"] = df["city"].astype("category")
  ```
* **Downcasting чисел:** перевод избыточных `int64` и `float64` в меньшие типы:
  ```python
  df["age"] = df["age"].astype("int8")  # возраст от -128 до 127
  df["user_id"] = df["user_id"].astype("int32")
  df["spend"] = df["spend"].astype("float32")  # 4 байта вместо 8
  ```
  Это уменьшает потребление памяти датафреймом в 3–15 раз.

## Parquet: практическое использование в ML

Parquet хранит данные колоночно и сжимает их блоками (по умолчанию алгоритмом Snappy).

```python
# 1. Базовая запись и чтение:
df.to_parquet("data.parquet", index=True)
df = pd.read_parquet("data.parquet")

# 2. Чтение только нужных колонок (быстрее в разы, не читает лишние байты с диска):
df_sub = pd.read_parquet("data.parquet", columns=["dept", "salary"])

# 3. Фильтрация на диске без загрузки лишних строк в RAM (Predicate Pushdown):
df_filtered = pd.read_parquet(
    "data.parquet",
    filters=[("experience_years", ">=", 10)],
)

# 4. Физическое партиционирование по папкам на диске:
df.to_parquet("by_department/", partition_cols=["dept"])

# Чтение только конкретной партиции (диск физически не открывает другие папки):
df_ml = pd.read_parquet("by_department/", filters=[("dept", "==", "ML")])
```

## Конструкторы данных (NumPy и pandas)

### Разница `shape` vs `size`:
* В геометрии тензоров (`zeros`, `ones`, `reshape`) аргумент формы матрицы называется **`shape`**.
* В вероятностных выборках (`rng.normal`, `rng.integers`, `rng.choice`) аргумент объёма выборки называется **`size`** (от термина *Sample Size*).

### Сводка конструкторов:
