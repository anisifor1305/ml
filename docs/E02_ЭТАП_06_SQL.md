## Источник и структура

Открытый taxis.csv из https://github.com/mwaskom/seaborn-data.
Исходный файл сохранён в exercises/data/e02/taxis_source.csv, URL и SHA-256 —
в source.json. Для упражнений взяты первые 300 строк исходника; trip_id — номер
исходной строки данных, начиная с 1. Это выборка, не все поездки города.
Результаты не обязаны представлять весь город; датасет не является данными клиентов
нашего сервиса тональности. Слой данных — отдельная часть инженерной сессии.

Справочник zones получен из непустых названий зон отправления/прибытия полного
исходника, zone_id присвоен по алфавиту. Это выполненная подготовка, не твоя задача.
Пропуски зон в поездках сохранены. Время сравниваем как местное календарное время
исходника, не преобразуем в UTC. Формат YYYY-MM-DD HH:MM:SS позволяет сравнивать
эти строки обычными <, <=, >= при едином формате.

SQLite-база создаётся в памяти при каждом запуске из trips.csv и zones.csv.
Имена таблиц: trips, zones, БЕЗ lesson10 и других схем.

### trips — одна строка на поездку (300 строк)

| Поле | Значение |
|---|---|
| trip_id | Учебный уникальный номер поездки; НЕ хронология |
| pickup_at | Дата и время начала поездки |
| dropoff_at | Дата и время окончания |
| color | Категория такси: yellow или green; это не ID машины |
| passengers | Записанное число пассажиров |
| distance | Фактическое расстояние, мили |
| fare | Базовая стоимость, доллары |
| tip | Чаевые, доллары |
| tolls | Платные дороги, доллары |
| total | Записанная итоговая сумма, доллары; используй как есть |
| payment | Способ оплаты; возможен NULL |
| pickup_zone_id | Ссылка на zones.zone_id для места отправления; возможен NULL |
| dropoff_zone_id | Ссылка на zones.zone_id для места прибытия; возможен NULL |

### zones — одна строка на зону (213 строк)

| Поле | Значение |
|---|---|
| zone_id | Уникальный учебный номер зоны |
| zone | Название зоны |
| borough | Городской район, например Manhattan |

Не нужно угадывать ID, менять CSV, удалять выбросы или добавлять фильтры,
которых нет в условиях. Все условия и направления сортировки заданы явно.

## 01 — зона отправления, LEFT JOIN

Сохрани все trips. Добавь название зоны отправления и её borough.
Столбцы: trip_id, color, total, название zones.zone AS pickup_zone, borough.
Порядок trip_id ASC. Нет известной зоны — NULL, ничего не подставлять.

## 02 — две зоны, два LEFT JOIN

Сохрани все поездки и добавь названия зон отправления И прибытия.
Один справочник zones используй дважды с разными псевдонимами.
Столбцы: trip_id, pickup_zone, dropoff_zone. Порядок trip_id ASC.
Не соединяй pickup_zone_id с dropoff_zone_id: каждый ссылается на zones.zone_id.

## 03 — статистика зон, LEFT JOIN и агрегация

Сохрани ВСЕ zones, включая зоны без отправлений в наших 300 поездках.
Присоедини trips по месту отправления.
Столбцы: zone_id, zone, trips_count, total_amount.
trips_count — число отправившихся поездок, без поездок 0.
total_amount — сумма total, без поездок NULL. Порядок zone_id ASC.
Используй GROUP BY. Не заполняй total_amount нулями.

## 04 — нумерация внутри категории такси

Используй ROW_NUMBER: отдельная нумерация для каждого color.
Хронология внутри color: pickup_at ASC, при равенстве trip_id ASC.
Столбцы: trip_id, color, rn. Порядок результата: color, pickup_at, trip_id — все ASC.

## 05 — предыдущая сумма

Для каждой поездки возьми total предыдущей поездки ТОГО ЖЕ color через LAG.
Порядок окна: pickup_at ASC, trip_id ASC. У первой в категории previous_total=NULL.
Столбцы: trip_id, color, total, previous_total.
Порядок результата: color, pickup_at, trip_id — все ASC.
Это ретроспективное упражнение: предыдущая по началу поездка могла ещё не закончиться.
Не объявляй previous_total безопасным признаком на момент начала текущей поездки.

## 06 — накопленная сумма

Суммируй total от первой до текущей поездки отдельно для каждого color.
Окно: pickup_at ASC, trip_id ASC; явно укажи
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.
Столбцы: trip_id, color, total, running_total.
Порядок результата: color, pickup_at, trip_id — все ASC.
Это также ретроспективная статистика, не признаки прогнозирования.

## 07 — итоги через WITH

В CTE собери для каждого непустого pickup_zone_id число поездок и сумму total.
Во внешнем SELECT оставь зоны, где trips_count >= 3.
Столбцы: pickup_zone_id, trips_count, total_amount.
Порядок: total_amount DESC, pickup_zone_id ASC.
Не нужны JOIN с zones и название зоны. Требование этапа — использовать WITH.

## 08 — витрина признаков одним запросом с WITH

Учебная задача: готовим сведения для прогнозирования total при начале поездки.
Разделительная дата: '2019-03-15 00:00:00'.

1. История: поездки, у которых pickup_at < дата, dropoff_at < дата
   И dropoff_at >= pickup_at. pickup_zone_id должен быть известен.
   Упрощение учебного сценария: total доступен сразу при завершении поездки.
2. В CTE агрегируй историю по pickup_zone_id: число поездок и среднее total.
3. Итоговые строки: ВСЕ поездки с pickup_at >= даты, даже если зона неизвестна
   или у неё нет истории. Других фильтров на итоговые строки не добавляй.
4. Прикрепи название зоны и borough из zones; статистику — по зоне отправления.
5. Без истории history_count=0, history_avg_total=NULL.

Ровно эти столбцы в этом порядке:
trip_id, pickup_at, color, pickup_zone, borough, history_count, history_avg_total.
Сортировка trip_id ASC. Весь результат — ОДИН запрос с WITH, не цепочка Python-циклов.
Фактические total, tip, distance, dropoff_at текущей поездки в итог не включай:
они относятся к её будущему. Не обучаем модель, собираем таблицу для возможного обучения.
