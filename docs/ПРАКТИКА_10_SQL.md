## Запуск сейчас: отдельный локальный PostgreSQL

Docker на момент подготовки не установлен. PostgreSQL 16 доступен.
Создан отдельный кластер `.lesson10_pg/`, без TCP-доступа: подключение только
через локальный Unix-сокет. Другие базы не затрагиваются.

Все команды ниже выполняются из `/Users/artem/coding/ml`.

```bash
.venv/bin/python scripts/lesson10_db.py start
.venv/bin/python exercises/lesson_10.py --task 1
```

`start` запускает сервер и загружает таблицы в схему lesson10; повторный запуск
не очищает таблицы. `--task 1` проверяет файл 01.sql. Без --task проверяются
все задания по порядку до первой ошибки или незаполненного TODO.

Успешная проверка печатает результат запроса. Маркер `\N` в выводе означает SQL NULL.
Проверяются названия столбцов, значения, дубликаты, число и порядок строк.
Запросы выполняются в транзакции только для чтения, с лимитом выполнения 10 секунд.
Проверка результатов не заменяет проверку способа решения и устных объяснений.

План заполненного запроса:

```bash
.venv/bin/python exercises/lesson_10.py --explain 6
```

Открыть интерактивный psql:

```bash
.venv/bin/python scripts/lesson10_db.py shell
```

В psql: `\dt` — список таблиц; `\d customers` — структура customers;
`\q` — выход. SQL завершается точкой с запятой.

Остановка сервера без удаления данных:

```bash
.venv/bin/python scripts/lesson10_db.py stop
```

## Docker: отдельный инженерный шаг по программе

Конфигурация: `infra/lesson_10/compose.yaml`, образ postgres:16.
Она запускает PostgreSQL в контейнере с отдельным хранилищем, публикует порт
только на 127.0.0.1:55410. Указанный пароль предназначен для локального обучения.
Для этого варианта требуется установленный и запущенный Docker с Compose.
Docker-вариант не запускался при подготовке, поскольку Docker отсутствует.

```bash
.venv/bin/python scripts/lesson10_db.py start --backend docker
.venv/bin/python exercises/lesson_10.py --task 1 --backend docker
.venv/bin/python scripts/lesson10_db.py shell --backend docker
.venv/bin/python scripts/lesson10_db.py stop --backend docker
```

Контейнерная и локальная базы независимы, но загружают одинаковые учебные данные.
В Docker при остановке данные сохраняются в томе. Команды удаления тома не требуются.
Перенос базы в Docker — отдельная незавершённая часть занятия, не условие для первого SELECT.

## Таблицы

- customers: 6 клиентов; customer_id — первичный ключ; name, city, age.
- orders: 7 заказов; order_id — первичный ключ; customer_id — внешний ключ,
  допускающий NULL; amount — NUMERIC(10,2); status — paid/cancelled/pending/refunded.
- tickets: 4 обращения; ticket_id — первичный ключ; customer_id — внешний ключ;
  status — open/closed.
- staff: 4 сотрудника; employee_id — первичный ключ; name; manager_id ссылается
  на staff.employee_id и может отсутствовать.
- cities: 3 города, столбец city.
- channels: 2 канала, столбец channel.
- blocklist: customer_id; намеренно содержит 2 и NULL.

Схема и исходные данные находятся в `infra/lesson_10/seed.sql`.
Здесь нет необходимости вручную писать CREATE TABLE или INSERT: это инфраструктура.
